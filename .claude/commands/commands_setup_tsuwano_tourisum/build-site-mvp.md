# /build-site-mvp — 津和野PRサイトの最初のMVPを作る

> Phase 0 (`/bootstrap`) の後に実行。環境構築 Phase 1〜8 は飛ばして構わない（初心者の最短ルート）。
> 一発で完璧を狙わない。**まず「動く1枚」を出す。** その後は Claude への直接依頼で伸ばす。
> Let's think step by step.

## このコマンドの目的

`project-brief.md` に込めた「津和野の想い」を、**実際に動く Next.js のトップページ**に変換する。
ここでのゴールは網羅ではなく **MVP（Minimum Viable Product）= ブラウザで開けて、津和野の
第一声と魅力が伝わる 1 ページ**。デザインの作り込みやセクション追加は後工程（Claude への直接依頼）。

## 環境チェックブロック

### Check 1: project-brief.md が記入済みか（最重要）

```bash
cat project-brief.md
```

`project-brief.md` を Read で読む。**`【　】`（空欄）が残っている場合は中断**し、
「先に `/bootstrap` を実行して発注書を完成させてください」と通知する。
特に ⑧（声のトーン）・⑩（禁止事項）・⑪（第一声）が埋まっていることを必ず確認する。

### Check 2: Node.js / npm

```bash
node --version 2>/dev/null
npm --version 2>/dev/null
```

無い場合は中断し、「Node.js (LTS) をインストールしてください: https://nodejs.org 」と通知。

### Check 3: 既存の web/ ディレクトリ

```bash
ls web/ 2>/dev/null
```

既にある場合、「上書きしますか? 既存を活かして続けますか?」と確認。上書き承認が無ければ続行モード。

### Check 4: モデル

`/model` で Sonnet を確認。MVP スキャフォールドは Sonnet で十分。

## 実行フロー

### Step 1: 発注書（project-brief.md）の要点を抽出

`project-brief.md` から、実装に使う要素を箇条書きで書き出し、参加者に「この理解で合っていますか?」と確認する:

| brief 項目 | サイトのどこに使うか |
|---|---|
| ⑪ トップの第一声 | ヒーローの一番大きい見出し（`<h1>`） |
| ② 15秒で言うと | ヒーロー下のリード文 |
| ① 津和野の呼び名 | サイトのキャッチ / メタ情報 |
| ⑤ 過ごす価値 / ③ 津和野だけのもの | 「津和野で過ごす」紹介セクション（3 点） |
| ⑦ 一番贈りたい気持ち | 全体の空気感・締めの一文 |
| ⑧ 声のトーン（3 語） | 文体・配色・余白の方針 |
| ⑨ 必ず使う言葉・モチーフ | 見出し語・画像の題材（例: 鯉／朝霧／畳の教会） |
| ⑩ 避けたい表現（禁止事項） | **書いてはいけないことの絶対基準**。生成前後に必ず照合 |
| ⑥ 来てほしいたった一人 | 文章の宛先（誰に語りかけるか） |

> **⑩ 禁止事項は最優先ガードレール。** 生成したコピーがこれに触れていないか、Step 4 で必ず自己照合する。

### Step 2: Next.js プロジェクトの雛形作成

`web/` に Next.js（App Router / TypeScript）を作成する。初心者が迷わないよう、対話は最小構成で固定する:

```bash
npx create-next-app@latest web --typescript --app --eslint --no-tailwind --no-src-dir --import-alias "@/*" --use-npm
```

> **Tailwind について**: 初心者向けに、まずは素の CSS（`app/globals.css`）で進める（`--no-tailwind`）。
> Tailwind を使いたい参加者は、MVP の後に「Tailwind を導入して」と Claude に頼めば切り替えられる。

作成後、起動確認の手順を参加者に案内（このコマンドからは起動しっぱなしにしない）:

```bash
cd web && npm run dev   # → http://localhost:3000 を参加者がブラウザで開く
```

### Step 3: トップページを brief で書き換え

`web/app/page.tsx` と `web/app/globals.css` を、Step 1 で抽出した内容で書き換える。方針:

- **ヒーロー**: ⑪の第一声を最大見出しに、②のリード文をその下に。
- **「津和野で過ごす」セクション**: ⑤/③/⑨ から 3 つの魅力カードを作る。
- **締め**: ⑦の気持ちを一文で。
- **配色・フォント・余白**: ⑧の 3 語から決める（例:「静か・誠実・文学的」→ 余白広め・明朝系・低彩度）。
- **文章の宛先**: ⑥の「たった一人」に語りかける文体。
- **メタ情報**: `app/layout.tsx` の `metadata`（title / description）に ① と ② を反映。

> **画像**: 実写がまだ無い段階では、`web/public/` にプレースホルダ（単色＋キャプション）を置き、
> 「ここに⑨のモチーフ（例: 朝霧の殿町通り）の写真を入れる」とコメントで明示する。著作権のある画像を勝手に使わない。

コードは初心者が読める粒度で、コメントを日本語で添える（勉強会の教材なので「なぜこう書くか」を残す）。

### Step 4: ⑩ 禁止事項との自己照合（Grill me）

生成したページの文言を、`project-brief.md` ⑩ の禁止事項リストと **1 項目ずつ照合**する:

> - ⑩に「『小京都』を多用しない」とあるのに使っていないか?
> - 殉教の歴史を「映えスポット」的に軽く扱っていないか?
> - ⑧の声のトーンから外れた（例: 禁止なのに『映え』連呼した）表現は無いか?
> - ⑥の宛先に向いた語り口になっているか?

触れている箇所があれば **必ず直してから** 次へ。参加者にも「禁止事項、守れていますか?」と確認する。

### Step 5: 動作確認

参加者に `cd web && npm run dev` を実行してもらい、`http://localhost:3000` をブラウザで開いて:

- [ ] ページがエラーなく表示される
- [ ] 第一声（⑪）が一番大きく見える
- [ ] 声のトーン（⑧）が伝わる
- [ ] 禁止事項（⑩）に触れていない

ビルドが通ることも確認:

```bash
cd web && npm run build
```

### Step 6: 進捗記録と次の一手

`.steering/_setup-progress.md` の「サイト実装トラック」の MVP 行を完了マーク（ファイルがあれば）:

```markdown
- [x] **MVP: /build-site-mvp**
  - 完了日時: [YYYY-MM-DD HH:MM]
  - 生成物: web/（Next.js）, トップページ（⑪⑧⑩反映済み）
```

参加者に次を案内:

```
MVP 完成です! ブラウザで津和野の第一声が見えていますね。

ここから先は Claude に直接お願いして 1 手ずつ伸ばします。頼み方のコツは
「まず project-brief.md を読んでから、○○して」と、発注書を起点にさせること。例:
- 「⑨のモチーフでセクションを1つ追加して」
- 「⑧の声のトーンと⑩の禁止事項に沿って文章を推敲して」
- 「写真ギャラリーを追加して（実写はプレースホルダで）」
- 「スマホ対応とアクセシビリティを整えて」

大きな変更の前は /clear でセッションをリセットすると安定します。
```

### Step 7: 発展メモ（公開と運用の方針）

今日の MVP から先、公開・運用まで進めたい参加者には次の方針を案内する（依頼すれば Claude が具体化する）:

- **公開（プライベート）**: **Cloudflare Pages** に載せ、**ユーザー名＋パスワード**で
  関係者だけが入れる形にする（Pages Functions の Basic 認証 `BASIC_AUTH_USER` / `BASIC_AUTH_PASS`、
  静的書き出し `output: 'export'`）。チーム運用なら Cloudflare Access への発展も可能。
  → 依頼例:「web/ を Cloudflare Pages にユーザー名＋パスワード付きでプライベート公開する手順を教えて」
- **保守・運用（発展）**: サイトの文章を **git 内の Markdown** に切り出し、**Sveltia CMS**
  （git ベースのヘッドレス CMS）の管理画面から非エンジニアでも編集できるようにする。
  Cloudflare 上で動かすため GitHub OAuth（Workers 認証）を併せて設定する。
  → 依頼例:「web/ のコンテンツを Markdown 化して Sveltia CMS で編集できるようにして」

## アンチパターン

- ❌ `project-brief.md` を読まずに一般的な「観光サイト」を作る（想いが入らない）
- ❌ ⑩の禁止事項を照合せずに公開文を書く（津和野を凡庸にする最大の失敗）
- ❌ 最初から全セクション・凝ったデザインを盛る（MVP を逸脱。まず動く1枚）
- ❌ 技術選定を参加者に細かく聞いて手を止める（Next.js 固定で即スキャフォールド）
- ❌ 著作権不明の画像を貼る（プレースホルダ＋コメントで明示）
- ❌ MVP の1コマンドで公開・CMS まで一気にやろうとする（それらは MVP 後に個別依頼で）
